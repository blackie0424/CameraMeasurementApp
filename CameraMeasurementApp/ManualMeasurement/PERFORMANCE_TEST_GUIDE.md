# 效能測試指南

本文件說明如何測試和驗證手動 AR 測量功能的效能表現。

## 測試目標

根據需求 3.5，我們需要驗證：

1. **即時預覽幀率**：目標 30+ FPS
2. **記憶體使用**：避免節點洩漏
3. **長時間運行穩定性**：確保應用程式可以穩定運行

## 效能監控工具

### PerformanceMonitor

系統已整合 `PerformanceMonitor` 類別，會自動追蹤：

- **FPS（每秒幀數）**：即時測量渲染效能
- **記憶體使用量**：監控記憶體消耗和峰值
- **節點數量**：偵測潛在的記憶體洩漏
- **會話時長**：追蹤應用程式運行時間

### 自動監控

效能監控會在以下時機自動啟動和停止：

- **啟動**：當 `ManualMeasurementViewController` 出現時（`viewWillAppear`）
- **停止**：當視圖控制器消失時（`viewWillDisappear`）

停止時會自動生成效能報告並輸出到控制台。

## 測試場景

### 1. 基本效能測試（短期）

**目的**：驗證基本測量操作的效能表現

**步驟**：

1. 啟動應用程式並進入手動測量模式
2. 執行 5-10 次完整的測量流程：
   - 記錄起點
   - 移動裝置（即時預覽）
   - 記錄終點
   - 重置測量
3. 觀察控制台輸出的 FPS 數值
4. 退出測量模式，查看效能報告

**預期結果**：

- 平均 FPS ≥ 30
- 無低 FPS 警告（< 25 FPS）
- 記憶體使用穩定

### 2. 即時預覽壓力測試

**目的**：驗證即時預覽的流暢度

**步驟**：

1. 啟動測量並記錄起點
2. 持續移動裝置 2-3 分鐘，觀察即時預覽線條
3. 注意畫面是否流暢，有無卡頓
4. 記錄終點並查看效能數據

**預期結果**：

- 即時預覽流暢，無明顯卡頓
- FPS 保持在 30 以上
- 無效能警告

### 3. 記憶體洩漏測試

**目的**：確保沒有節點洩漏

**步驟**：

1. 啟動測量模式
2. 重複執行 20-30 次測量循環：
   - 記錄起點
   - 記錄終點
   - 重置（重新測量）
3. 觀察控制台的節點數量變化
4. 查看最終報告的洩漏檢測結果

**預期結果**：

- 節點數量保持穩定（不持續增長）
- 無「潛在洩漏」警告
- 記憶體使用量穩定

### 4. 長時間運行穩定性測試

**目的**：驗證長時間使用的穩定性

**步驟**：

1. 啟動測量模式
2. 持續使用 10-15 分鐘，包括：
   - 多次測量操作
   - 移動到不同環境
   - 測試不同距離
   - 偶爾讓應用程式閒置
3. 監控記憶體和 FPS 趨勢
4. 退出並查看完整報告

**預期結果**：

- 應用程式保持穩定，無崩潰
- 平均 FPS 保持在目標值
- 記憶體使用量不持續增長
- 無效能降級

### 關鍵指標

#### FPS（每秒幀數）

- **目標**：≥ 30 FPS
- **可接受範圍**：25-35 FPS
- **警告**：< 25 FPS
- **說明**：即時預覽的流暢度指標

#### 記憶體使用

- **正常範圍**：50-150 MB
- **警告閾值**：> 200 MB
- **說明**：應用程式的記憶體消耗

#### 節點數量

- **正常範圍**：5-20 個節點
- **警告**：持續增長且超過 50 個
- **說明**：場景中的 3D 物件數量

#### 低 FPS 事件

- **可接受**：< 5 次
- **需注意**：5-10 次
- **有問題**：> 10 次
- **說明**：FPS 低於 25 的次數

## 效能優化建議

### 如果 FPS 過低

1. **檢查節流機制**：確認更新間隔設定為 1/30 秒
2. **減少 Hit Test 頻率**：只在需要時執行
3. **優化渲染**：重用節點而非重建
4. **簡化幾何體**：使用更簡單的形狀

### 如果記憶體持續增長

1. **檢查節點清理**：確保 `clearAllVisuals()` 正確移除節點
2. **檢查強引用**：避免循環引用
3. **檢查紋理和材質**：確保正確釋放
4. **使用 Instruments**：進行深度記憶體分析

### 如果偵測到節點洩漏

1. **檢查重置邏輯**：確保每次重置都清除舊節點
2. **檢查節點層級**：確保子節點也被移除
3. **使用 weak 引用**：避免保留不需要的節點引用

## 使用 Xcode Instruments 進行深度分析

### Time Profiler

1. 選擇 Product > Profile（⌘I）
2. 選擇 Time Profiler
3. 執行測量操作
4. 查看哪些方法消耗最多 CPU 時間

### Allocations

1. 選擇 Product > Profile（⌘I）
2. 選擇 Allocations
3. 執行多次測量循環
4. 查看記憶體分配趨勢
5. 使用 Mark Generation 功能追蹤洩漏

### Leaks

1. 選擇 Product > Profile（⌘I）
2. 選擇 Leaks
3. 執行長時間測試
4. 查看是否有記憶體洩漏

## 故障排除

### 問題：FPS 低於預期

**可能原因**：

- 裝置效能不足
- 場景過於複雜
- Hit test 執行過於頻繁

**解決方案**：

- 在較新的裝置上測試
- 簡化視覺元素
- 增加節流間隔

### 問題：記憶體持續增長

**可能原因**：

- 節點未正確移除
- 循環引用
- 紋理未釋放

**解決方案**：

- 檢查 `clearAllVisuals()` 實作
- 使用 weak 引用
- 使用 Instruments 分析

### 問題：應用程式崩潰

**可能原因**：

- 記憶體不足
- 存取已釋放的物件
- AR Session 錯誤

**解決方案**：

- 查看崩潰日誌
- 使用除錯器追蹤
- 檢查錯誤處理邏輯

## 結論

完成所有測試場景並確認效能指標符合要求後，即可認為效能測試通過。如有任何指標未達標，請參考優化建議進行改進。
